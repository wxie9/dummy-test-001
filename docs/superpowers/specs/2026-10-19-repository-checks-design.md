# 主分支保护与基础检查设计

日期：2026-10-19。范围：按用户要求配置 main 的 PR 合并约束、文档链接检查和误提交大文件检查。

## 检查与规则

- 每个发往 main 的 PR 和 main 的 push 均运行两个稳定命名的检查：`Documentation links`、`Large files`，不使用路径过滤以免必需检查缺席。
- 文档使用固定版本 lychee 检查 Markdown 中仓库内的目标和锚点，包括图片、引用式链接；代码片段不视为实际链接。外部网站连通性不作为合并门槛。
- 大文件按现有约定以 10 MiB 为上限，等于上限允许，超过上限失败。检查 HEAD 的全部受 Git 跟踪文件，并检查本次 PR/推送引入的历史 blob，防止加入后删除的大文件漏检。仅检查 Git 对象元数据，不读取语料/权重内容。LFS 指针检查其 Git blob 大小，远端内容不属于此检查范围。
- 检查脚本仅依赖 Python 标准库和 Git；CI 使用只读 contents 权限、不持久保存 checkout 凭据，固定第三方 Action commit 与 lychee 版本。
- main 要求 PR、两个由 GitHub Actions 提供的检查通过、分支保持最新、讨论已解决；管理员也适用；禁止 force push 和删除。不新增管理员绕过名单。
- 当前只有一个仓库管理员，因此 required approving reviews 设为 0，保留 PR 要求；团队评审约定继续适用，不启用无法满足的他人审批。

## 实施顺序与验收

1. 先建立大文件检查的真实临时 Git 仓库测试，观察实现缺失失败，再实现检查。
2. 在临时目录验证 lychee 能拒绝坏路径/锚点，并确认现有文档通过。
3. 创建 PR 运行实际 Actions，检查两个检查的名称、来源 App 与结果。
4. 通过 GitHub API 配置保护并读回验证，再按该保护正常合并 PR，不使用管理员绕过。
5. 同步 main，确认远程保护和 main 的 Actions 检查通过，记录操作方式与边界。
