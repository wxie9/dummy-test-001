# JEV 科研协作骨架设计

日期：2026-10-19。状态：按对话中已确认方案实施。

## 目标与范围

用一个 Git 仓库承载多人共同进行的文献调研、湿实验记录、计算分析和阶段汇报。第一版交付可直接使用的中文说明、记录模板、协作模板和存储边界。项目具体科学问题、成员名单、编程语言和外部存储尚未确定，不预设这些信息。

## 方案选择

- 采用统一主仓库：跨文献、实验和代码的关联在一个 PR 中即可检查，适合当前启动阶段。
- 多仓库方案留待组件具有独立发布和权限需求时采用。
- 电子实验记录本可在湿实验录入量增长时接入；当前先用 Markdown 模板，并保留外部记录链接字段。

## 信息架构

`literature/` 保存检索记录、文献笔记、综述和 BibTeX；`research/` 保存问题、假设和决策；`protocols/` 保存方案版本；`experiments/wet/` 与 `experiments/computational/` 分别保存实验记录和计算运行记录；`metadata/` 保存样本、数据集和匿名成员标识；`src/`、`notebooks/`、`workflows/`、`tests/` 保存分析实现；`reports/` 保存周报、阶段报告和图表说明。

`templates/` 是记录模板的唯一来源，各目录 README 负责解释用途并链接模板。`.github/` 提供任务和 PR 模板。

## 关联与状态

文献使用稳定引用键；问题和假设使用 `Q-`、`H-` 编号；方案使用 `P-` 编号和独立语义版本；样本使用 `S-` 编号；实验使用 `E-` 编号；计算运行使用 `R-` 编号；数据集使用 `D-` 编号。除文献与方案版本外，编号格式为前缀、创建日期、唯一成员代号、三位序号。每位成员维护自己的序号，创建前搜索冲突。

研究记录应区分观察事实、分析结果、解释与下一步。状态与结果分别描述：失败、无显著差异和结论不明确均可作为有效记录，不用“已合并”表示科学结论已验证。

计算运行记录输入数据版本、代码 commit、工作区是否存在未提交修改、参数、环境、执行命令和产物。提交运行记录产生的新 commit 不应倒填为执行时的代码 commit。

## 协作与存储

采用 Issue、短期分支、PR 评审流程。每项实验、运行或文献笔记分别建文件；公共索引发生冲突时追加并保留双方记录。方案更改后发布新版本，历史实验保持引用原版本。日志的更正追加说明；Git 历史记录修改过程。

Git 保存文本、配置、元数据、经挑选的轻量产物和小型测试数据。原始数据、模型、大型附件、个人标识映射和凭据保存在外部，仓库仅保存持久定位、版本、校验和及访问说明。第一版不部署 DVC、Snakemake、MLflow 或 ELN，不安装第三方 skills，不配置远程分支保护，不邀请成员或发布 Issue。

`AGENTS.md` 提供项目内 AI 工作规则；自定义 skills 待实际工作流验证后提炼，避免规则与模板重复维护。

## 验收

1. 新成员能按 README 找到各类模板，并完成从任务到 PR 的操作。
2. 文献、方案、湿实验、计算运行、问题、假设和周报均有模板。
3. 编号规则、模板字段、目录说明一致；所有相对文档链接存在。
4. GitHub Issue Forms 可解析，必填字段和 ID 合法；目录不包含伪造实验记录。
5. 用临时虚构记录演练文献—实验—运行的关联、未完成状态及失败结果的记录方式。
6. `git diff --check` 无错误。交付独立分支、提交和草稿 PR，供团队评审；不直接合并至 `main`。
