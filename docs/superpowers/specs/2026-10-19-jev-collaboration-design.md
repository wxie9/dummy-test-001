# JEV LLM 协作骨架设计

日期：2026-10-19。状态：按用户确认的大语言模型训练与评测范围实施。

## 目标与范围

一个 Git 主仓库管理多人文献调研、LLM 实验计划、训练、评测与阶段汇报。第一版提供中文说明、记录模板、元数据表、GitHub 任务与 PR 模板。实现面向 Python 与启动脚本；具体训练框架、GPU、模型、依赖版本与外部存储由首个实际任务确定。

## 架构

literature/ 保存检索与阅读；research/ 保存问题、假设和决策；experiments/ 保存计划与独立训练/评测运行；benchmarks/ 保存版本化评测协议；configs/、src/、scripts/ 分别承载参数、实现与启动入口；metadata/ 登记成员、数据、基础模型和 checkpoint；reports/、notebooks/、tests/ 支持汇报、探索与验证。

一个主仓库能在同一 PR 中检查文献、代码和记录的关联。多仓库拆分待出现独立发布、权限或组件复用需求后再评估。模板是字段唯一来源，目录 README 解释用途。

## 关联与记录

文献用稳定引用键；问题 Q、假设 H、决策 DEC、检索 L、实验计划 E、训练 TR、评测 EV、协议 B、数据 D、外部模型 M、checkpoint C 使用稳定编号。格式为前缀-YYYYMMDD-MEMBER-NNN，成员先注册，创建前检查冲突。

训练固定代码 commit、数据版本/split、模型与 tokenizer revision、实际配置、资源、seed、日志与 checkpoint。恢复运行使用新 TR-ID，关联源 checkpoint 与恢复状态。执行时的代码 commit 和随后提交运行日志的 commit 分开记录；dirty 运行保存含未跟踪文件的完整快照。

评测固定模型/checkpoint、数据 split、协议版本、prompt/chat template、few-shot、解码、指标与聚合、有效分母、失败条目处理和原始输出。基线比较核查条件；测试集调参边界和污染检查在计划/协议中说明。使用模型裁判和效率指标时记录相应条件。

状态与结果分别记录，失败与中断也保留，不能将运行结束、loss 下降或 PR 合并自动解释为能力提升。

## 协作与存储

Issue 分为文献、训练、评测；采用短分支和 PR 评审。一个计划、训练或评测独立建文件，公共表保留并发追加并检查唯一键。新协议另建版本，不覆盖已被引用的版本。

Git 保存代码、配置、日志摘要、元数据与小型 fixture；语料、tokenized 缓存、权重、完整预测及运行日志在外部保存，以 URI、revision 和 SHA-256 关联。当前没有真实数据/运行，不部署训练平台、CI、第三方 skills 或远程分支保护。

## 验收

1. README 能引导新成员找到文献、计划、训练、评测协议与评测日志。
2. 编号、目录与模板字段一致；4 张 TSV 只有表头；相对文档链接存在。
3. 训练模板覆盖 checkpoint 与恢复状态；评测模板覆盖精确输入与可比条件。
4. 3 个 Issue Forms 可解析且结构有效；Git 忽略大型产物与凭据，保留记录与测试数据。
5. 在临时目录演练文献—计划—训练—checkpoint—评测关联、失败训练和未执行评测；不向仓库写入模拟科研结果。
6. 检查完整 diff，交付分支和草稿 PR，不直接合并 main。声明未执行训练/评测及尚未配置的资源。
