# 数据管理

## 存储边界

| 内容 | 存储方式 |
| --- | --- |
| Markdown、BibTeX、代码、配置、环境锁定文件、TSV 元数据 | Git |
| 小型、可共享的测试数据 | `tests/fixtures/`，说明来源与用途 |
| 精选报告图表 | `reports/figures/`，关联生成它的运行记录 |
| 原始仪器文件、大型图像、测序数据、模型、大量运行结果 | 团队共享存储；本地副本放 Git 忽略目录 |
| 文献 PDF | Zotero 共享库或约定的附件存储 |
| 个体身份映射、凭据和访问令牌 | 独立受限存储；不进入 Git |

建议普通 Git 中单个文件控制在 10 MiB 内；这是本项目的起步约定。较大文件先确定外部存储方案，不能靠改扩展名或压缩绕过管理规则。`.gitignore` 不会阻止强制添加，也不会忽略已跟踪文件，提交前仍需检查。

## 外部存储的最低要求

当前尚未配置共享存储；确定后在本文补充实际地址、维护成员代号、申请访问方式与备份安排。远端共享文件不能仅存在于某位成员的个人电脑。

1. 原始采集数据保留不变；处理、筛选和格式转换产生新数据或新版本。
2. 每个数据版本在 [数据集表](../metadata/datasets.tsv) 中登记：ID、版本、来源实验/公开来源、共享定位、清单 SHA-256、负责人、访问说明。
3. 单文件可直接记录文件的 SHA-256；目录应生成列出相对路径和各文件 SHA-256 的清单，保存清单 URI，并记录清单自身的 SHA-256。
4. 元数据中的 URI 应为团队长期可定位的位置，避免过期签名链接、带令牌的 URL 和个人绝对路径。访问凭据另行配置。
5. 外部存储需要独立备份和恢复抽查；Git 的备份不能恢复未进入 Git 的数据。

单文件校验示例：macOS 使用 `shasum -a 256 文件路径`；Linux 使用 `sha256sum 文件路径`。校验和从真实文件计算，不手填猜测值。

## 样本与记录的关系

[样本表](../metadata/samples.tsv) 维护稳定样本 ID、来源实验 ID、匿名父样本 ID、采集日期和记录路径。重复测量引用同一样本；派生样本或独立样本使用新 ID，并记录父子关系。表中的 ID 不编码个人信息。

数据集表按 `(dataset_id, version)` 唯一，多个输入以分号连接。对公开数据保留 accession/DOI、下载日期、精确版本或文件校验和。样本表只存项目允许共享的最少信息，个体身份映射由外部受限系统维护。

## 后续工具接入

- 外部存储确定并需要数据切换时，可用 DVC 管理版本指针；共享数据还需执行数据上传，单独 `git push` 不会上传外部文件。
- 多步骤分析稳定后，可引入 Snakemake 或其他流程工具，并登记软件版本与环境。
- 模型训练运行数量增加后，再考虑 MLflow 等运行对比工具。
- 使用 ELN 时，在实验记录中保留记录 ID 与永久链接，明确哪一处保存权威原始记录，避免双份记录互相冲突。

本仓库当前不包含这些服务的配置，也没有默认数据源或默认计算环境。
