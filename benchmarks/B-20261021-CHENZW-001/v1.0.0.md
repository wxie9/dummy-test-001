## 数据与模型接口

- 数据集：`D-20261021-CHENZW-001@0.3:public-index`。只使用公开 0.3 suite；0.4 榜单的私有测试和新域私有任务不在本协议范围。
- 测试集用途、调参边界和污染检查：仅作最终评测；不得用公开题或答案调提示、阈值、权重、训练数据或模型选择。每次运行须声明已知训练重叠和是否构建过 suite；私有部分由维护方执行，不能据此协议复现。
- 模型接口：每个 request 只向 engine 传入 `state` 与 `questions`。每个 choice 选项须返回概率，所有选项概率之和为 1；yes/no 使用上游 `noul` 格式。接口验证、拒答和异常语义以 `decision_index/engines/` 为准。
- tokenizer revision 与特殊 token：待实际运行时登记在 EV 记录；本协议不假定某一模型或 tokenizer。
- prompt/system prompt/chat template：使用上游 engine 的固定渲染；若使用 `transformers` engine，保存其 chat-template 是否启用和其精确内容/来源 revision。不得按 benchmark 定制 prompt。
- zero/few-shot 设置：zero-shot；不使用示例。若上游未来 task 配置改变，发布新协议版本。
- 上下文长度、截断策略、输出解析与后处理：不得截断选项或丢弃题目；超出容量标记为 `unsupported`，其他失败按上游 runner 记录。

## 执行与计分

- 解码参数：选择式 readout，不采样；实际 engine、模型 revision、精度、设备、最大长度、任何 HTTP 参数与 seed 均写入 EV 记录。
- 评测框架精确版本/commit 与 task 配置：`src/evaluation/decision-index` 的上述提交；运行使用 `--edition 0.3`，并保存生成 suite 的 manifest 与哈希。
- 指标定义：每 benchmark 先计算原生指标并纳入覆盖率（未答、拒答、错误、弃答均视为错），然后按上游 chance level 转成 skill；五个 area 加权得到 0–100 的 public `index`。同时保存 `raw_index`、per-benchmark summary、area 分数和完成状态。
- 重复次数、误差/置信区间处理：一次完整确定性 readout；如模型或服务含随机性，另行声明重复次数、seed 与聚合，不能与单次结果直接比较。
- 失败/超时/重试：遵循上游 runner；`error` 可在 resume 时重试，`unsupported` 与 `abstained` 为最终状态且计入未答。不得删行或以有效样本子集报分。
- 模型裁判：不用。
- 效率比较：不在本协议中比较；若报告延迟，保存硬件、精度、并发、预热、请求长度分布和计时边界。
- 结果需要保存：外部存储中的 `results.jsonl`、`benchmark-summary.json`、`index.json`、`scores.json`、`environment.json` 与 suite manifest；Git 只保存 EV 记录和可公开的摘要。
