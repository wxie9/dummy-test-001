## 数据与模型接口

- 数据集：`D-20261021-CHENZW-004@1.2:public`。固定使用上述提交中 `datasets/public/original.jsonl`（72 题）、`easy.jsonl`（48 题）、`hard.jsonl`（111 题），共 231 题。按 [datasets/manifest.json](https://github.com/fstandhartinger/jevbench/blob/609a664e81f46e03731600bd7bd9f1b7a61257c5/datasets/manifest.json) 的对应 split 行数与文件 SHA-256 核验；该 manifest 标识为 `jevbench::v1.2`，还包含本协议不使用的其他 split。
- 范围与可比性：不使用 heldout、router、judge、easy-heldout、额外公开扩展或密封题；不重新生成、混入或筛选题目。该 231 题集合和下述 CLI 指标不能作为 JevBench v1.6.0/v1.6.1 完整榜单总分，也不能与其直接比较。模型适配器不同的结果须另外说明可比性。
- 测试集用途、调参边界和污染检查：公开题只能用于最终评估，不能用于训练、蒸馏、提示选择、阈值选择或测试集驱动的模型选择。每个 EV 记录必须声明模型训练数据与公开题目的已知重叠。
- 模型接口：使用固定提交的 `jevbench.tasks.Task` 与选定的 `jevbench/adapters/` 实现，保留 `state`、`question`、`labels`；`expected` 只供计分，不传入模型。输出必须为完整 label 概率分布，本协议不采用 label-only 路径。实际 adapter、API、响应 schema、tokenizer revision 和特殊 token 固定到 EV 记录。
- prompt/system prompt/chat template：固定题目的 `question` 和所选上游 adapter 渲染；保存 adapter 文件路径、commit、配置及实际 prompt/chat template。不得按题目或分数定制；新建 adapter 时先提交其实现并修订协议。
- zero/few-shot 设置：zero-shot，不增加 demonstrations；模型/adapter 原有提示须在 EV 中完整记录。
- 上下文长度、截断策略、输出解析与后处理：不丢题、不删选项。超长、无效格式、拒答、超时和解析失败按上游 evaluator 的失败规则保存和计分。

## 执行与计分

- 解码参数：在 EV 记录保存模型/权重 revision、temperature、top-p、max tokens、seed、停止条件、批大小、并发、超时与重试。
- 评测框架精确版本/commit 与 task 配置：在本仓库外获取 JevBench 并 checkout 上述提交，以其 `jevbench.cli` 的 `run` / `summarize` 为入口。它不是本项目子模块，`src/evaluation/jevbench` 不存在。运行记录保存外部 checkout 路径、`git rev-parse HEAD`、环境、三个题目文件哈希、manifest 哈希和 adapter 配置。
- 指标与计分入口：逐项使用固定提交的 [jevbench/scoring.py](https://github.com/fstandhartinger/jevbench/blob/609a664e81f46e03731600bd7bd9f1b7a61257c5/jevbench/scoring.py) `score_task`，聚合使用 [jevbench/summarize.py](https://github.com/fstandhartinger/jevbench/blob/609a664e81f46e03731600bd7bd9f1b7a61257c5/jevbench/summarize.py) `summarize`。`noul`、`choice`、`score` 的正确性均按最大概率 label 与 gold 精确匹配，概率相同时取字典序最小 label；`score` 另报期望等级的 `ordinal_mae`。不改用后续方法文档中的 Noul 阈值/Score nMAE 或 composite 聚合。
- 概率校验：沿用 `score_task` 的 `SUM_TOL=1e-3`、`RENORM_TOL=2e-2`；满足舍入容差时按上游归一化，超出容差、label 缺失/多余或非有限值均为无效且计错。同时保留 `strict_valid`、`renormalized` 与原始概率，不能自行修复输出。
- 汇总字段与分母：保存完整 summary，以 `macro_accuracy`（有可计分项的 family accuracy 均值）为本公开集合的主要指标，同时报 `accuracy=n_correct/n_scorable`、`per_family`、`n_planned`、`n_attempted`、`n_scorable`、`n_valid`、coverage 和 schema validity。`n_scorable` 按上游规则只排除原题 `expected=None` 或 `provenance.exclude_reason` 非空的项；运行前固定这些 ID、原因与数量。失败项仍在适用的计分分母中，不因模型表现增删排除项。
- 重复次数、误差/置信区间处理：一次完整运行；该 CLI 不提供本协议的置信区间，不虚构区间。非确定性模型的 seed、服务端随机性与限制记录到 EV；若追加重复运行，分配新 EV-ID，分别报告分数。
- 失败/超时/重试：保存逐项状态、最终错误及实际 adapter 的超时/重试设置。API/解析失败和无效分布按上游计错；预算耗尽或中断导致缺失记录时标为未完成，不报告可比的主要指标。计分前必须确认 231 个题目 ID 各有且仅有一条结果、`n_planned=n_attempted=231`、`complete=true`；不得用 CLI 对不完整记录输出的分数作为完整评测结果。
- 模型裁判：不用；题目已有 gold，涉及判断其他答案的题目也仍是被测模型的任务。
- 效率比较：不在本协议中比较。
- 结果需要保存：外部存储保存公开数据 manifest、三个文件的哈希、运行 manifest、含原始概率/失败状态的逐项结果、CLI summary、原始响应、日志与环境；Git 只保存 EV 记录及可公开摘要。

