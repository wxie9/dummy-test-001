# toolcall_valid

Generated tool calls (difficulty v2): is the proposed call correct for the request under the tool's schema?

- Decision: whether a proposed tool call is valid under the tool's JSON schema, keeps the rules of its description and carries every value that the user request fixes, directly or indirectly (yes), or breaks the schema, a rule or the request (no).
- Item source: generated by `build/gen_toolcall_valid.py` (`random.Random(20261007)`, standard library only, no input file); labels programmatic; licence: generated by the benchmark's script (no third-party text); items included.
- Rows: 600 (300 yes, 300 no); metric: accuracy (chance 0.5). Rebuild: `python3 build/gen_toolcall_valid.py`; the first version (flat schemas, params 4/6/8) is `DIFFICULTY = "v1"` at the top of the script.

## What is generated

Every item is a tool schema in JSON, a user request and a proposed call in JSON, under a fixed block of judging conventions. The schema has 6, 9 or 12 top-level properties: scalars (identifiers, dates, counts, enum words, yes/no flags, names, codes, amounts with a currency), a nested object (name, e-mail, phone), an array of objects with its own required fields, ranges and size limits (order lines, shifts, passengers, cost items, delivery stops), and one computed parameter (a total, a count). The tool description states 1, 2 or 3 rules across parameters: a date may not precede another; a code is only allowed for one value of another parameter; exactly one of the two contact fields is given; a total equals a sum over the array (quantity times price, a field, hours); a count equals the number of entries; every entry's day lies in the period; every hour window runs forward. The request fixes values indirectly as well as directly: dates as the last day of a month, the n-th weekday of a month or a number of days from another date; line items as a quantity at a price each (so the total must be computed); and look-alike identifiers: after an identifier a bracket names another one, with one transposed pair of digits, that must not be used. Five invented tools (order, rota, trip, claim, delivery run) with 15 to 19 properties in the pool each. The words of the request never equal a parameter name of the schema unless they set that parameter (a cost item is a bill, not a receipt, next to the flag `receipt`); filler sentences come from a pool of 44; a language is named ("Dutch") while the call carries its code. The 300 positives are correct calls that exercise the same structures (arrays of 2 to 8 entries, boundary values, indirect dates, look-alikes, rules at their limits); each has a twin with exactly one planted deviation. Both rows of a pair are scored as separate items; a bootstrap that resamples by `meta.pair` accounts for their correlation.

## Dial

`meta.level` = 1, 2, 3 for `meta.params` = number of top-level properties 6, 9, 12 (200 rows each, 100 yes and 100 no). More properties bring more rules (1, 2, 3), a nested object from 9 on, and longer arrays (2-3, 3-5, 4-7 entries). State length: 3225-4824, 3913-5898 and 4867-6850 characters.

## Deviation kinds (`meta.deviation`, number of no-items per dial level)

| kind | what is wrong | level 1 (params 6) | level 2 (params 9) | level 3 (params 12) | total |
|---|---|---|---|---|---|
| missing | a required field is missing: at the top level (an unnamed optional one is added), in one array entry, or in the nested object | 17 | 16 | 17 | 50 |
| enum | one step outside an enum, a range or the size of the array (the request asks for it, or the call sets an unnamed field) | 17 | 16 | 17 | 50 |
| type | a string for a number or a boolean, an object where the schema says array, a string where it says object | 17 | 17 | 16 | 50 |
| value | a near miss that contradicts the request: one day off, a transposed pair of digits (often the look-alike named in the request), a price one hundredth off | 17 | 17 | 16 | 50 |
| extra | an undefined field at the top level, in an array entry or in the object, or a field of another level at the wrong level | 16 | 17 | 17 | 50 |
| rule | one rule of the tool description is broken: date order, total or count off by the smallest step, a second contact field, a code without its condition, a day outside the period, an hour window that does not run forward | 16 | 17 | 17 | 50 |

Where the deviation sits (`meta.deviation_where`): top 85, element 177, object 30, array 8. Rule deviations by rule: count 8, date_order 8, elem_order 6, one_of 8, only_when 7, sum 7, within 6.

Indirect dates per request: mean 1.6. Vocabulary test worst rate ratio: 1.20 (words), 1.14 (all tokens).

## Checks run by the script

- `truth2(spec)` on the structured specification (`meta.spec`) and `check2(item)` on the state text alone agree on all 600 items; every negative has exactly one violation, of the planted kind, at the recorded path; the correct member of every pair has none.
- Exact balance: 300 yes / 300 no; 100 + 100 per dial level; 16 or 17 deviations per kind and level (50 per kind). The two members of a pair have the same number of top-level arguments.
- Vocabulary test: no word (and no token) of frequency >= 20 is more than twice as frequent in one class as in the other.
- Name collisions (gen_v4): no word of the request equals a parameter name of the schema (the whole name in singular or plural, or one part of it split at the underscores) unless the phrase sets that parameter; the words of the tool's own name (create_order: create, order) and date expressions ("the last day of ...") are exempt. The test runs on the whole library (every phrasing, filler sentence and enum word of every tool against every name the tool can have) and on the request of every item and of both members of every pair; invented names, titles and e-mail domains are drawn so that they do not equal such a word.
- Languages (gen_v4): the request names the language ("replying in Dutch"), the call carries the code (`nl`); the schema says that the value is a two-letter ISO 639-1 code, and `parse_request2` maps the name back to the code.
