# Kev 七套评测数据集构成与任务分类

本文整理 Kev 实验中使用的七套评测数据集：`decision-v7`、`transfer-v4`、`transfer-v9`、`hard-v1`、`devtools-v1`、`documents-v1` 和 `breadth-v1`。前六套的数字直接来自本地官方 `test.jsonl`；`breadth-v1` 的公开仓库没有完整 `test.jsonl`，其构成来自官方 `manifest.json`。

## 1. 统计口径

- `record`：一条输入材料。一条 record 可以带多个问题。
- `question`：一个实际计分子问题。
- `choice`：从多个候选答案中选择一个。
- `noul`：二分类判断，例如“是/否”“成立/不成立”“调用/不调用”。
- `score`：预测有序等级，例如 1–5 星或风险档位。
- `clean`：正常评测样本，是本文准确率分母使用的主要口径。
- `none_present`：加入“以上都不是”，但原正确答案仍然存在。
- `none_absent`：移除原正确答案，此时应选择“以上都不是”。
- `permuted`：打乱选项顺序或呈现方式。

`transfer-v9` 的 clean 数据包含 110 道 `unknowable` 题。这些题故意删除决定答案所需的关键证据，主要评估模型是否降低置信度，不按普通答对/答错计分。因此：

- 七套评测共有 6,936 条 clean record；
- clean 数据中共有 9,198 个问题对象；
- 扣除 110 道置信度题后，普通准确率的总分母是 9,088 题。

## 3. decision-v7：基础决策能力

`decision-v7` 最接近 Kev 的基础训练分布，混合了主题分类、意图识别、自然语言推断、评分和规则执行。

| 来源 | Records | Questions | 任务 |
|---|---:|---:|---|
| AG News | 80 | 240 | 新闻主题分类；同时判断是否属于世界、体育、商业、科技 |
| Amazon Reviews | 80 | 80 | 预测评论星级 |
| Banking77 | 80 | 80 | 银行业务意图分类，例如转账失败、退款、卡被吞 |
| BoolQ | 80 | 80 | 根据文章回答是/否问题 |
| Contrastive | 160 | 160 | 根据政策、约束或组合规则作决策 |
| DBpedia14 | 80 | 80 | 实体或主题类别分类 |
| IMDb | 80 | 80 | 影评正负面判断 |
| MNLI | 80 | 80 | 蕴含、中立、矛盾三分类 |
| SST-5 | 80 | 80 | 五级情感强度评分 |
| TREC | 80 | 80 | 问题类型分类，例如人物、地点、数字、实体 |
| Yelp | 80 | 160 | 同时预测评分和是否推荐 |
| **合计** | **960** | **1,200** |  |

它主要覆盖五类能力：

1. 意图与主题分类；
2. 情感和评分；
3. 自然语言推断；
4. 是非决策；
5. 政策和组合规则执行。

完整文件还包含 `none_present`、`none_absent` 和 `permuted` 鲁棒性变体。我们之前报告的准确率使用 clean 部分。

## 4. transfer-v4：第一层分布外迁移

`transfer-v4` 不再重复 `decision-v7` 的基础来源，而是换成新任务、新标签和新的规则组合，测试模型能否把已有决策能力迁移到未见分布。

| 来源 | Questions | 题型 | 任务 |
|---|---:|---|---|
| composition_holdout | 96 | choice | 训练中未见过的规则或政策组合 |
| contrastive | 80 | noul + score | 对比决策、政策判断和等级预测 |
| Emotion | 80 | choice | 细粒度情绪分类 |
| MMLU | 80 | choice | 多学科知识与推理题 |
| PAWS | 80 | noul | 两句话是否互为释义 |
| QNLI | 80 | noul | 给定句子是否回答了问题 |
| SciQ | 80 | choice | 科学知识选择题 |
| Tweet Offensive | 80 | noul | 推文是否包含攻击性内容 |
| **合计** | **656** |  |  |

主要能力包括新任务迁移、新标签语义理解、组合规则泛化、知识问答、语义匹配和安全分类。

## 5. transfer-v9：困难迁移和缺失信息

`transfer-v9` 保留 `transfer-v4` 的主要任务，同时增加更难的知识题、干扰文本和信息缺失实验。

| 来源 | Questions | 任务 |
|---|---:|---|
| composition_holdout | 96 | 未见规则组合 |
| contrastive | 80 | 对比政策和等级判断 |
| Emotion | 80 | 情绪分类 |
| MMLU | 80 | 多学科知识 |
| MMLU-Pro | 200 | 选项更多、难度更高的知识与逻辑题 |
| PAWS | 80 | 释义判断 |
| QNLI | 80 | 问答蕴含判断 |
| SciQ | 80 | 科学问答 |
| Tweet Offensive | 80 | 攻击性内容判断 |
| buried | 80 | 从大量无关文本中找到真正需要执行的任务 |
| unknowable | 110 | 删除关键证据，评估模型是否承认不确定并降低置信度 |
| unknowable_control | 110 | 与 unknowable 配对，但保留完整证据 |
| **合计** | **1,156** |  |

普通准确率不包含 110 道 `unknowable` 题，因此实际分母为：

`1,156 - 110 = 1,046`

`buried` 主要测试模型在长上下文和无关信息中识别真正任务的能力；其内部包含答案识别、情绪、攻击性和释义等子任务。

## 6. hard-v1：七类复杂推理

`hard-v1` 是后来“薄弱能力续训”最重要的压力测试之一。

| 原生类别 | Records | Questions | 具体任务 |
|---|---:|---:|---|
| 信息不足 `hard_ambiguous` | 100 | 100 | 条件不充分、事实冲突或无法确定答案 |
| 答案校验 `hard_judge` | 100 | 188 | 判断答案、推导或计算是否正确，并在需要时给出正确值 |
| 长政策 `hard_long_policy` | 100 | 200 | 阅读保险、赔付和制度类长文本，判断结果及金额 |
| 多跳推理 `hard_multi_hop` | 100 | 125 | 依赖图、组织关系、服务影响链和控制链推理 |
| 概率 `hard_probability` | 100 | 158 | 概率、期望值、风险档位和事件可能性比较 |
| 时间与数值 `hard_temporal_numeric` | 100 | 117 | 日期、期限、时区、周期、付款和退款金额 |
| 约束权衡 `hard_tradeoff` | 100 | 200 | 在硬约束和多个软目标下选择最优方案 |
| **合计** | **700** | **1,088** |  |

需要区分两套“七类”定义：

- `hard-v1` 原生七类是信息不足、答案校验、长政策、多跳推理、概率、时间与数值、约束权衡。
- 我们后续续训报告里的七类包含工具路由和提示注入，是把 `hard-v1` 与 `devtools-v1` 重新组合得到的业务分类，并不等于 `hard-v1` 原生 family。

## 7. devtools-v1：开发工具和安全决策

`devtools-v1` 的六个来源各包含 150 条 record。

| 来源 | Records | Questions | 任务 |
|---|---:|---:|---|
| Aegis | 150 | 175 | 判断内容是否不安全；不安全时进一步判断风险类别 |
| CodeReviewer | 150 | 150 | 判断代码 diff 是否值得添加审查意见 |
| CommitPackFT | 150 | 298 | 判断代码变更类型，以及提交信息是否与变更匹配 |
| FlakeFlagger | 150 | 150 | 判断测试是否会随机失败，即 flaky test |
| Prompt Injection | 150 | 150 | 检测提示注入攻击 |
| When2Call | 150 | 150 | 决定调用工具、追问信息、直接回答或无法回答 |
| **合计** | **900** | **1,073** |  |

它对应六类能力：内容安全、代码审查、代码变更理解、测试稳定性、提示注入检测和工具路由。

在我们后续的薄弱七类分析中：

- “工具路由”主要来自 `When2Call`；
- “提示注入”主要来自 `Prompt Injection`。

## 8. documents-v1：金融长文档分类

`documents-v1` 全部来自 CFPB 消费者投诉文本。

| 来源 | Records | Questions | 任务 |
|---|---:|---:|---|
| CFPB | 574 | 936 | 根据消费者投诉文本预测金融产品和投诉问题 |

它包含两类主要标签：

1. `product`：投诉涉及的金融产品，例如信用卡、按揭贷款、债务催收、信用报告和银行账户。
2. `issue`：投诉的主要问题，例如错误收费、无法退款、账户被冻结、信用报告错误和催收行为。

并非每条 record 都同时包含两个问题，因此共有 574 条投诉文本和 936 个分类问题。这套数据主要测试长文档信息抽取、金融领域分类、相近标签区分，以及从大量事实中识别主要矛盾。

## 10. 七套评测之间的关系

| 层次 | 数据集 | 主要测量内容 |
|---|---|---|
| 基础分布 | `decision-v7` | 常规分类、评分、推断和政策决策 |
| 普通迁移 | `transfer-v4` | 新任务、新标签和新规则组合 |
| 困难迁移 | `transfer-v9` | MMLU-Pro、干扰文本、信息缺失和置信度 |
| 深度推理 | `hard-v1` | 长政策、多跳、概率、时间数值和约束优化 |
| 工具与安全 | `devtools-v1` | 工具路由、提示注入、代码和测试判断 |
| 文档理解 | `documents-v1` | 金融长文档和细粒度标签分类 |
| 能力广度 | `breadth-v1` | 推理、工具、检索、合同、偏好和国际象棋 |

这七套数据并不是七份同质的“准确率测试”。`decision-v7` 更接近基础分布，`transfer-v4/v9` 主要看迁移，`hard-v1`、`devtools-v1` 和 `documents-v1` 分别强化复杂推理、工具安全和长文档能力，`breadth-v1` 则检查能力覆盖面。因此分析模型变化时，应同时看总体分数和各套数据的能力构成，不能只比较一个加权总分。
