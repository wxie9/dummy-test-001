# v9 完整续训结果与下一步

本轮训练和评测已完成，但没有达到“两模型七类都明显提升”的目标。Qwen3 的七类合计从 512/1000 到 513/1000，修复 57 题、新增错误 56 题；Qwen3.5 从 551/1000 到 578/1000，修复 58 题、新增错误 31 题。总分不能掩盖单类退化。

| 类别 | 题数 | Qwen3 原 stage3 → v9 | Qwen3.5 原 stage3 → v9 |
|---|---:|---:|---:|
| 工具路由 | 150 | 52 → 51 | 34 → 62 |
| 时间 | 117 | 44 → 45 | 51 → 49 |
| 概率 | 158 | 85 → 81 | 87 → 83 |
| 信息不足 | 100 | 66 → 64 | 69 → 72 |
| 多跳 | 125 | 61 → 57 | 85 → 87 |
| 长政策 | 200 | 117 → 111 | 131 → 126 |
| 注入 | 150 | 87 → 104 | 94 → 99 |

Qwen3 有五类下降；Qwen3.5 的时间、概率、政策下降。Qwen3 合计变化的成组 bootstrap 95% 区间为 −2.04 至 +2.33 个百分点；Qwen3.5 为 +0.79 至 +4.58 个百分点。这些是固定诊断题的单种子结果，区间未作多重比较校正，不代表独立泛化或训练种子稳定性。

本轮确有 1500 道基础情境：350 概率、270 多跳、280 信息不足、300 政策及工具/时间/注入各 100；额外 1020 条配对视图和 6000 条回放分别计数。两模型都从各自原始 stage3 开始，学习率 1e-5、LoRA rank 16、一轮 1065 步。实际读取 8520 条记录，无长度过滤或截断。训练耗时 Qwen3 1319.73 秒、Qwen3.5 1513.08 秒。用户再次要求完全不改的三类 300 道训练题已与 v5/v6/v7 逐行核验一致，日期边界表述也保持原样。

## 学到了什么，没学到什么

Qwen3.5 在合成训练集的正赔付金额视图上，从 6/325 提高到 162/325；开发集从 4/74 到 35/74。但训练集应赔 0 的视图从 255/275 降到 185/275，开发集从 46/46 降到 31/46，说明消除一部分“总选 0”偏好同时带来了新错误。更关键的是，真实政策测试的正赔付金额从 17/35 降到 11/35；那 8 道应赔正金额且提供 0 候选的真实题仍 8/8 选 0。真实应赔 0 的 65 道金额题仍全部正确，因此不能把真实政策总分下降概括为“误赔变多”；真实回退主要在正金额计算和部分结论判断。

Qwen3 在合成训练集正赔付视图上只从 0/325 到 11/325，开发集从 0/74 到 2/74。它连训练内的这项能力也没有充分学会。真实政策应赔 0 的结论判断从 28/65 到 19/65，金额却仍 65/65 正确，两个输出之间的不一致变多。

若要求一对视图的全部子问题都答对，训练集 Qwen3 的概率仅 5→9/350，多跳依赖 9→10/90，政策 3→6/300；Qwen3.5 为 10→20/350、10→26/90、5→38/300。信息不足的配对学习更明显：训练集 39→97/280、69→154/280，开发集 12→29/70、17→38/70；但真实信息不足只表现为 Qwen3 下降 2 题、Qwen3.5 提高 3 题。合成题上的改善尚未稳定迁移到真实题。

## 下一项受控检验

按实际训练代码、seed 101 和 8520 条输入的顺序复算，1020 个配对组没有一组在同一个 microbatch 或同一次参数更新内一起出现；两视图间隔的中位数为 306 个优化步骤。独立交叉熵训练本身是合法的，这不证明打散是失败原因。

下一项候选固定这份数据、原 stage3 起点和现有交叉熵目标，只把显式配对组放入同一个 microbatch，检验训练顺序的影响。三个保留类别不修改，不新增所谓“独立题量”。分组也会改变随机梯度和增强变体的归一化系数，应作为训练调度对照报告，不能声称只改变了某一个梯度因素。

候选已在 6 个随机种子 × 3 个模拟 epoch 的 18 份顺序上核验：每份均保留全部 8520 条记录，每条一次，1020 对全部同批，仍为 1065 步。修改基于这轮实际归档的旧版 stage3 训练代码，而非后来下载的新版本。当前只有调度器与隔离训练源码候选，尚未启动下一轮；部署前仍需真实回放身份核对和模型训练预检。
