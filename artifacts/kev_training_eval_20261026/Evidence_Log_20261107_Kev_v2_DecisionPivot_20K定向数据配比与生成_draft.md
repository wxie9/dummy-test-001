## 1. Last Meeting’s Actions

### 1.1 已完成：把 DecisionPivot 弱项转成可执行的数据配额

此前已将 DecisionPivot 拆为13个任务族、45个细分类，并得到 Kev-27B v1 与 StartLux Instant 的逐类差距。配额设计没有平均分配2万条，而是同时考虑：

1. Kev 在该细类上与 StartLux 的准确率差距；
2. 该细类在评测集中的题量；
3. 当前95,047条候选语料对该能力的已有覆盖；
4. 某些标签仍是合并桶时，不能把估计覆盖伪装成精确计数。

第一步为每类计算优先级：

```text
priority_i = gap_pp_i × sqrt(eval_n_i)
```

其中 `gap_pp_i` 是 Kev 相对 StartLux 落后的百分点，`eval_n_i` 是该细类的评测题数。使用平方根而不是直接乘题量，是为了让大类得到更多数据，但不让大类完全淹没小而困难的类别。

第二步将优先级映射为建议最终覆盖量，原始目标范围约500–1,500条，总目标为35,300条。再从建议目标中扣除现有覆盖：

```text
raw_deficit_i = max(0, target_i - current_i)
```

对于仍然合并、无法精确拆开的覆盖桶，使用 `0.5 × target_i` 作为暂定缺口，而不是虚构精确已有量。所有原始缺口合计26,756条，再统一缩放到本轮预算20,000条：

```text
allocation_i = round_to_25(raw_deficit_i × 20,000 / 26,756)
```

因此，本轮20K是“第一批定向修复配额”，不是经过训练效果反推后的最终最优比例。

### 1.2 已完成：实现结构化生成器和确定性求解器

新增代码将题目生成拆成两层：

- **结构化层**：程序生成事实、图、日志、账本、状态转换、规则或约束，并由确定性求解器计算唯一答案；
- **语言层**：DeepSeek只负责把已经求解的状态改写成自然语言题面和选项，不允许改变事实或标签。

结构化层覆盖12个实际新增任务族：事实判断、权限继承、政策判断、日志计数、排期冲突、状态目标、分诊排序、条款变化、依赖解析、账本核对、记录规则和条件筛选。

### 1.3 已完成：生成并审核20,000条自然语言训练候选

自然语言渲染使用 `deepseek-v4-flash`，调用 DeepSeek 官方 OpenAI-compatible 接口。每个批次包含两次模型调用：

1. 根据结构化 scaffold 生成题面、问题和选项文字；
2. 用独立的忠实度提示检查数字、时间边界、逻辑连接词、例外规则、单位、图边、操作顺序和选项语义是否改变。

未通过本地格式检查或第二次忠实度审核的样本不会进入正式文件，而是进入拒绝记录等待重试。最终所有20,000条均完成渲染并通过跨层审计。

## 2. Blockers

### 2.1 已解决：初始API凭据指向无余额旧账号

第一次主轮使用了本机旧 `.env` 中的 DeepSeek Key。官方余额接口显示该Key余额为−0.26元，因此生成到2,431条后，大量请求返回 `HTTP 402 Insufficient Balance`。该问题不是数据生成逻辑错误，也不是用户所说余额362.30元的账号没钱，而是调用了错误账号。

换用用户确认的新Key后，官方余额接口返回362.30元。生成器从2,431条断点续跑，没有重新生成或重复计费前面的已完成样本。凭据只存在于运行进程环境中，没有写入代码、JSONL、manifest或日志。

### 2.2 已解决：最后39条的网络中断和忠实度拒绝

第二轮主生成结束时剩余39条：

- 32条：API响应流提前断开，错误为 `IncompleteRead(0 bytes read)`；
- 7条：自然语言渲染被第二轮忠实度审核拒绝，原因是选项含义或条件表述与结构化 scaffold 不完全一致。

这些样本改为单条请求、两路并发重试，最终全部补齐。历史39条拒绝记录保留为 `rendered.rejected.previous-pass-20261107.jsonl`，它表示已解决的前一轮失败，不是最终数据仍有39条缺失。

### 2.3 尚未解决：训练前仍缺三项独立验证

当前审计证明数据内部结构、数量、哈希和标签映射一致，但还不能直接称为“训练就绪最终集”。仍需：

1. **分层人工抽查**：检查题面是否自然、是否存在求解信息不足、干扰项是否合理；
2. **冻结集污染检查**：对 DecisionPivot、Kev 六套冻结测试和其他计划评测集做 exact / n-gram / MinHash 重叠检查；
3. **目标 tokenizer 长度检查**：统计 Qwen3.8-27B tokenizer 下的长度分布和截断比例。

### 2.4 评测解释边界

DecisionPivot 的错误类型参与了本轮类别选择和配额设计。因此，后续在同一 DecisionPivot 上的提升是定向修复证据，不是独立盲测。六套 Kev 冻结测试、未参与设计的新 DecisionPivot 同构题，以及未见领域数据必须作为泛化护栏。

### 3.3 生成方式：答案由程序计算，LLM只写语言表面

每条样本按以下顺序产生：

```text
固定seed
  → 生成结构化世界状态
  → 确定性求解器计算答案和求解轨迹
  → 构造常见错误对应的干扰项
  → 随机打乱选项位置
  → DeepSeek生成自然语言题面
  → DeepSeek第二次审核语义忠实度
  → 本地校验ID、选项键、标签和结构哈希
  → Kev格式JSONL
```

各任务族的程序求解逻辑如下：

| 任务族 | 结构化状态 | 确定性求解器 |
|---|---|---|
| 事实判断 | 实体、关系边、表格数值 | 图遍历、继承查询和跨表聚合 |
| 权限继承 | 用户、角色链、授权、拒绝、作用域 | 权限图遍历和覆盖规则 |
| 政策判断 | 有优先级的规则、例外和案例字段 | 按优先级逐条求值 |
| 日志计数 | 时间窗口、边界语义、事件和过滤器 | 精确过滤和计数 |
| 排期冲突 | 时间区间、容量、设备和既有预订 | 约束满足检查 |
| 状态目标 | 初始状态、操作步骤和目标条件 | 状态转换模拟 |
| 分诊排序 | 类别、严重度、时效和并列规则 | 多字段稳定排序 |
| 条款变化 | 旧条款、新条款和案例 | 修改前后分别求值再比较 |
| 依赖解析 | 版本域、约束、依赖图和已安装节点 | 版本交集与依赖闭包 |
| 账本核对 | 条目、金额、费用、日期和批次声明 | 算术与完整性核对 |
| 记录规则 | 原始字段、派生字段和作用域 | 重新计算派生字段并校验依赖范围 |
| 条件筛选 | 候选对象、阈值、证书、条件规则和单位 | 约束求值与单位换算 |

### 3.4 生成过程中发现并修复的三个数据问题

#### 问题A：小样本测试通过，但全量出现结构碰撞

最初部分生成器使用随机整数组合。几十条 smoke 数据没有重复，但扩展到500条以上后出现相同结构状态。修复方式不是简单增加随机ID，而是把关键数值改成按index覆盖的混合进制组合，使真实算术状态、时间状态或约束状态不同。最终20,000条结构语义哈希全部唯一。

#### 问题B：某些错误类型几乎只有一个标签

第一版中，“版本冲突”几乎全部为 `conflict`，“账本错误”几乎全部为 `invalid`，“状态失败”几乎全部为 `not_achieved`。模型可能只学到题型或措辞捷径。修复后，每个错误类型加入同结构的反事实控制样本：一半真正触发错误，一半满足条件。最终任一细分类中，最大单一语义答案占比为66.8%。

#### 问题C：公开状态包含求解器派生结果

第一次DeepSeek smoke 中，条款题的结构化状态包含 `old_decision` / `new_decision`，状态题包含 `final_state`，账本题包含 `expected_total`。这些字段会把答案直接写进题面。修复后，上述派生结果仅保留在求解器私有轨迹中，不再发送给语言模型。最终审计确认公开状态中不存在这些答案泄露字段。
