# 数据质量结论

## 数据粒度

训练集的分析单位是“独立语义情境”。每个情境有两个表述视图；development 每个情境只有一条。模型文件按各自七个薄弱类别过滤，combined 文件再加入上一批错题邻域数据。

## 检查结论

| 检查 | 结果 | 风险等级 |
|---|---|---|
| 记录/题面唯一性 | 新数据和组合数据均为 0 重复 | 通过 |
| train/development exact state 交集 | 0 | 通过 |
| 冻结 test exact state 交集 | 0 | 通过 |
| 双视图结构 | 1,350/1,350 情境均为两视图，标签与题型一致 | 通过 |
| 代码来源组隔离 | 三类 train/development 组交集均为 0 | 通过 |
| Kev 结构读取 | 全部记录可 materialize | 通过 |
| 二分类/CommitPackFT 主标签平衡 | 二分类严格均衡；七类 change type 每类 42–44 条 | 通过 |
| tokenizer 长度预检 | 尚未在目标 H20 tokenizer 上运行 | 高风险、待处理 |
| 独立人工标签复核 | 尚未进行 | 中风险、待处理 |
| 语义/模板近重复 | exact 检查无法排除 | 中风险、已记录 |

最大剩余风险是长政策题可能超过训练上下文限制。正式训练前应把四个模型文件逐条跑 `fits(materialize(record), tokenizer, **training_context(7552))`，要求拒绝数为 0；若有拒绝，只修剪被拒绝的长政策记录并重新生成清单和哈希。第二项优先工作是每类随机抽查至少 20 个独立情境，重点复核 CommitPackFT 的 message_match、代码审查和提示注入负例。
