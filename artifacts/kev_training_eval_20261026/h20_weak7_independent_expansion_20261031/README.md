## 数据怎样生成

- 时间、概率、工具路由：使用确定性规则生成器重新抽取事实并复算标签，不读取冻结测试题。
- 多跳推理、长政策：使用 Kev 官方 hard-v1 家族生成器，但更换独立随机种子；标签由官方 solver 从保存的事实重新计算。
- 提示注入：组合新的攻击/防御性提及模板、敏感对象、动作、目标和载体，攻击与非攻击各占一半；标签由是否包含直接不可信指令的规则给出。
- 代码审查、代码变更理解、测试稳定性：从 devtools-v1 的原始训练分区抽取。官方 development/test 的 ID、来源组和题面全部排除；新 train/development 再按项目或仓库组隔离。
- 每个训练情境的第二条记录只改变题面呈现、diff hunk 行号、测试类命名空间、字段布局或选项顺序；事实、问题、标签和选项含义不变。

代码类新 train/development 的来源组交集为 0：CodeReviewer 为 79/3 个组，CommitPackFT 为 148/29 个组，FlakeFlagger 为 9/3 个组。

## 已完成的质量检查

- 1,350 个训练情境全部恰好有两条训练表述。
- 同一情境两条表述的问题、题型、标签和选项内容一致，题面不同。
- 全部 JSONL 可由 Kev `load_records` / `materialize` 读取。
- 新训练集、新 development 及其交叉之间没有完全相同题面。
- 与本地所有冻结测试 JSONL 的 exact state 重叠为 0。
- 记录 ID 和题面哈希无重复；4B/9B 组合文件也通过相同检查。
- CodeReviewer、FlakeFlagger、提示注入的二分类训练标签均为 150:150；CommitPackFT 的七种 change type 为 42–44 条，基本均衡。
- 所有输出文件 SHA-256、来源哈希和限制记录在 `manifest.json`；具体检查结果在 `audit.json`。

## 尚未完成的检查与使用边界

当前状态是候选数据已生成、模型尚未训练。目标 H20 上对应 Qwen3.5 tokenizer 的 7,552-token `fits` 预检尚未执行；长政策题最需要这项检查。标签也没有经过独立人工复核。

“1,350 个独立训练情境”指事实或原始代码样本不同；2,700 条记录中的第二条是同情境改写，不能算成 2,700 个独立问题。exact state 不重叠也不能排除题型或模板层面的相似。

4B/9B 的 `combined` 文件含前一批由 hard-v1/devtools-v1 错误定向生成的数据。因此训练后在这两套题上的变化仍属于定向修复回测，不能写成独立盲测泛化；应继续看六套冻结测试及新的来源隔离 development。
