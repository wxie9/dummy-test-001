> 调研截止：2026-11-09（Asia/Shanghai）

## 0. 先说结论

10 月 20 日之后，真正值得关注的“训练出一个 Jev 类模型”的工作主要有六组：

1. **Jev-Style 2B v4/v4.2**：约 1.88B，最轻量、最容易在本地复现和做消融。
2. **EO-Jev**：约 8.4B，多模态 Earth Observation 专用模型；论文、训练代码、权重和完整评测链都公开，是这一批里证据链最完整的工作。
3. **Sarvam Prism**：105B 总参数、约 10B 激活的 MoE；开源权重，但显存门槛很高。
4. **IOTA Decide 4B**：4B，开源权重，强调分散式训练和多问题共享 state 计算；模型论文和完整训练代码尚未公开。
5. **Drex 系列**：8B / 9B / 35B-A3B / 27B 多模态，采用 SFT + RLAF、稳定性损失等训练；运行代码和权重公开，但不同 checkpoint 的许可证不同。
6. **RELOAD**：不是一组全新 backbone，而是对 395M、400M、1B、0.6B、1.7B、4B 六个模型做自适应 latent looping；它是最值得拿来改造现有 Kev/H20 训练栈的方法论文。

如果目标是给当前 SEA / FutureX / H20 工作选可执行方向，优先级建议是：

- **第一优先：复现 RELOAD 的 adaptive looping**，先放到 4B 上验证“困难样本多循环、简单样本少循环”是否真的改善 hard-v1 / devtools-v1。
- **第二优先：引入 Jev-DLC 的 typed feedback 状态更新**，因为它直接对应 self-evolving agent 的在线纠错和个性化，但不要求在线反向传播。
- **第三优先：补齐可靠性评测**，至少加入 multi-select、选项排列、presentation、prompt injection、跨语言阈值和长链闭环六个轴。
- **模型基线**：Jev-Style 2B v4.2、IOTA Decide 4B、Drex v1.5 9B、EO-Jev（若做多模态领域适配）。Prism 和 Drex v2.0 更适合作为大模型上界，不适合直接当低成本主线。

## 2. 逐项详解：新模型和训练方法

### 2.1 Jev-Style 2B Decision v4 / v4.2

### 链接

- 项目主页：https://jevstyle.com/models/
- GitHub：https://github.com/lawrence3699/jev-style
- Hugging Face（v4.2 BF16）：https://huggingface.co/chaoliangUNSW/Jev-Style-2B-Decision-v4.2
- Hugging Face（v4.2 GGUF）：https://huggingface.co/chaoliangUNSW/Jev-Style-2B-Decision-v4.2-GGUF
- Hugging Face（v4.2 MLX）：https://huggingface.co/chaoliangUNSW/Jev-Style-2B-Decision-v4.2-MLX
- v4 权重：https://huggingface.co/chaoliangUNSW/Jev-Style-2B-Decision-v4
- arXiv：**截至 2026-11-09 未发现独立技术论文**。

### 模型规模与接口

- 实际参数：**1,881,825,088，约 1.88B**；项目对外常写 2B 或 2.2B。
- 基座：Qwen3.5-2B-Base。
- 最大输入：32,768 tokens，图像 token 也计入限额。
- 单个问题最多 255 个候选选项。
- PyTorch 版本支持文本和图像；GGUF / MLX 版本目前是 text-only。
- 多个问题可以共享同一 state 的文本计算，避免为每个问题重复编码。

### 怎么训练的

- 目标是复现 Jev 式 `choice` / `noul` / `score` typed decision 接口，而不是生成答案文字。
- 使用了硬标签和软标签；模型卡明确写到一部分软标签由 **TypeSafe Jev 1.14 公共 API 蒸馏**而来。
- 因此它更接近“Jev 蒸馏 + 开源小模型”路线，不是从纯人工标注独立训练出的基础 decision model。
- Apache-2.0 权重和代码，便于本地改 head、loss 和数据混合策略。

### 公开结果

- v4.2 在 Decision Index 0.3 的公开部分自测为 **46.74**，v4 为 **44.37**，提升 2.37 分。
- 作者报告完成 140,178 个可评分请求，且独立 CPU 重算复现了 46.74。
- 这是 public-only 自测，不等于私有榜单的 Full score，也不等于独立第三方验证。

### 我怎么看

- 优点：体量小、格式完整、许可证宽松，最适合做 head、loss、calibration、looping 和 online adaptation 消融。
- 风险：蒸馏自 Jev，容易继承 teacher 的偏差；公开分数低于更大的新模型；图像路径与 GGUF/MLX 路径不完全一致。
- 对当前项目的价值：很适合当 **2B 低成本下界**，也适合快速验证 RELOAD / Jev-DLC，而不是当能力上界。

### 2.2 EO-Jev: Decision Model for Earth Observation

### 链接

- arXiv：https://arxiv.org/abs/2611.03371
- GitHub：https://github.com/mbzuai-oryx/EO-Jev
- Hugging Face：https://huggingface.co/mx297/EO-Jev
- 项目主页：https://mbzuai-oryx.github.io/EO-Jev/

### 模型规模与架构

- 基础模型：d3-flash，约 **8.4B**，以 Qwen3.5-9B 为 backbone。
- Decision readout：在最后 prompt token 上使用最多 255 个 code 的线性 readout。
- 训练时对 vision blocks、vision merger、text tower 加 LoRA；训练后把 adapter 合并，所以推理架构和成本与 d3-flash 基本相同。
- LoRA rank：text tower 32、vision merger 64、vision blocks 16；视觉模块学习率为主学习率的 0.2 倍。

### 数据和训练

- 只使用公开 Earth Observation 数据集的训练划分，覆盖六类任务：
  - 场景与土地利用；
  - VQA；
  - 计数；
  - 多时相变化；
  - 建筑损伤与灾害类型；
  - 地理定位。
- 每个 batch 约混入 **20% 通用 decision replay**，减轻领域适配后的通用能力遗忘。
- 用 perceptual hash 对所有训练图像和评测图像做近重复检查。
- 训练目标是 KL divergence，加上针对 ordinal 问题的 ranked probability score。
- 官方 recipe：20,000 steps，每步 16 个问题；4 张 A100 约 25 小时。

### 结果

- 在 30 个 setting 中有 26 个显著优于 d3-flash。
- 域内平均提升 **+23.8 points**。
- 12 个 held-out setting 平均提升 **+8.0 points**。
- 在 28 个可比 setting 中，20 个达到或超过最佳开源 EO specialist；21 个有更低 ECE。
- 吞吐量约为 specialist 中位数的 **6.4×**；若每次只问一个问题，约 3.2×。
- 通用 decision 能力下降约 **1.8 points**，说明 replay 只能缓解、不能完全消除 forgetting。

### 局限

- 计数、变化量估计、灾损分级、目标缺失判断仍然困难。
- 离训练分布较远时校准会明显变差。
- option order 仍可能影响结果；typed output 不能自动解决 presentation sensitivity。

### 我怎么看

- 这是截止日最完整的训练型工作：代码、权重、数据转换、leak check、训练、评测和分析脚本都公开。
- 它给 SEA 最直接的启发不是“做遥感”，而是 **领域 LoRA + 通用 replay + proper scoring rule + 完整去重审计** 这一套 recipe。
- 如果以后要把 H20/SEA 做成领域模型，这个工作应当作为训练与证据链模板。

### 2.3 Sarvam Prism

### 链接

- 官方发布：https://www.sarvam.ai/blogs/sarvam-prism
- Hugging Face 权重及推理代码：https://huggingface.co/sarvamai/prism
- GitHub：**没有单独的官方 GitHub；推理实现 `prism.py` 直接放在 Hugging Face 仓库中。**
- arXiv：**截至 2026-11-09 未发现独立 arXiv 技术报告。**

### 模型规模与架构

- 总参数：**105B**。
- MoE 每 token 激活：约 **10B**。
- 基于 Sarvam-105B。
- 每层 128 个 routed experts；FP8 权重采用 per-output-row scale，activation 采用 per-token scale。
- decision head 读取每个 option 末尾和 answer marker 的 hidden state，返回各候选项概率。

### 部署成本

- Hugging Face 文件约 106GB 级别。
- 官方说明需要大约 **120GB 可用 GPU memory**，测试硬件为 B200 / H200。
- 权重和推理代码为 Apache-2.0，但“开源”不等于“普通单卡可运行”。

### 结果与稳定性设计

- 官方博客报告其综合三个 index 的平均分为 71.8，并报告 B200 上约 44ms；这些数字是厂商自报，不能直接与不同硬件、不同榜单版本混比。
- Prism 会对 options 做 canonical internal sort。官方 2,000 例测试中，option shuffle 的 top-choice flip 为 0。
- 这个设计说明 option-order robustness 可以部分通过输入规范化工程解决，不一定全靠训练学出来。

### 我怎么看

- 它是“大型 MoE + 小 decision head”的上界路线，和 2B/4B 小模型不是同一个成本区间。
- 对当前 H20 主线最有价值的不是复现 105B，而是复现其 **canonical option ordering**，作为低成本强 baseline。
- 缺少独立论文、训练细节和第三方 sealed-set 复验，结论要保守看待。

### 2.4 IOTA Decide 4B

### 链接

- Hugging Face：https://huggingface.co/macrocosm-os/iota-decide-4b
- GGUF：https://huggingface.co/macrocosm-os/iota-decide-4b-GGUF
- IOTA 分布式训练框架：https://github.com/macrocosm-os/IOTA
- IOTA 框架论文（背景，不属于 10 月 20 日后新论文）：https://arxiv.org/abs/2507.17766
- 模型专属 arXiv：**截至 2026-11-09 未发现。**
- 模型完整训练仓库：**截至 2026-11-09 未公开；上面的 GitHub 是 IOTA 通用分布式训练框架，不应写成此模型的完整训练代码。**

### 模型规模与接口

- 参数：**4B dense**。
- 基座：Qwen3.5-4B。
- 在 backbone 上增加 joint schema head。
- 一次请求中的多个问题共享 state computation，输出 `noul`、`choice`、`score` 三类概率。
- BF16 权重约 9GB；GGUF Q8_0 约 4.5GB；Q4_K_M 约 2.7GB。
- Apache-2.0。

### 训练特色

- 重点是 **disaggregated compute**：由多台独立单 GPU 机器跨网络协同，而不是传统同机多卡集群。
- 模型卡披露了训练数据来源，但截至截止日没有模型级完整训练脚本、采样过程、loss 配方和可复现实验日志。
- 其价值一半在模型，一半在“是否能用异构闲置卡做 decision fine-tuning”这一工程命题。

### 结果口径

- 模型卡给出 JevBench 公开 231 题的作者自测，并明确说明 sealed-set 官方评测尚未完成。
- 因此可用于 sanity check，不能作为确定的 leaderboard 排名。

### 我怎么看

- 它是当前最合适的 **4B 开源对照**：大小接近现有 Kev 4B，接口标准，单卡容易部署。
- 如果当前实验只和同源 Kev 比，加入 IOTA 4B 能帮助区分“训练 recipe 提升”与“模型族特有优势”。
- 不建议在论文里声称复现其训练，除非作者后续公开完整 model-specific pipeline。

### 2.5 Towards Foundation Decision Models: Drex

### 链接

- arXiv：https://arxiv.org/abs/2611.07854
- GitHub：https://github.com/nace-ai/drex-decision-models
- Drex v2.0（35B-A3B）：https://huggingface.co/nace-ai/drex-v2.0
- Drex v1.5（9B）：https://huggingface.co/nace-ai/drex-v1.5
- Drex DLM（8B）：https://huggingface.co/nace-ai/drex-dlm
- Hugging Face Paper 页面：https://huggingface.co/papers/2611.07854

### 家族规模

| 模型 | 参数 | 架构 | 说明 |
|---|---:|---|---|
| Drex DLM | 8B | Efficient-DLM-8B | diffusion language model 路线 |
| Drex v1.5 | 9B | MiMo-V2.6-Distill-Qwen-9B + Kev pointer head | 10B 以下主力 checkpoint |
| Drex v2.0 | 35B 总参数、约 3B 激活 | Qwen3.6-35B-A3B MoE + Kev pointer head | 大权重、低激活参数，但内存仍是 35B 级 |
| Drex Max | 27B | multimodal | 论文中的多模态高能力版本 |

### 训练方法

- 先做 typed-decision SFT。
- 再做 **RLAF**：同时使用可验证 outcome reward 和 reasoning judge reward，并用 KL constraint 防止策略偏移过大。
- 加入 consistency / stability 类损失，减少 option-order 和接口表述变化造成的波动。
- Max 额外做视觉任务适配。

### 结果

- 论文报告 Drex Max 在 Decision Index 0.4.1 public 为 **67.52**，Jev 1.14 为 60.70；private 为 66.60。
- 作者报告 option-order flip 从 6.3 降至 4.2。
- v1.5 在作者的 Decision Index 0.3.1 public-only 自测中为 58.08；和 Jev、Nimble 的差距处在榜单 tie band 附近，不能解读为显著领先。
- v2.0 BF16 约需 70GB，Q8 约 37GB；默认 context 16K，可扩至 131K。

### 开放性和许可证

- 运行时、服务端、llama.cpp / Ollama 分支和 checkpoint 页面公开。
- GitHub 主要是 runtime、模型说明和服务代码；论文给出训练 recipe，但不等于所有训练数据和一键训练流水线都完全公开。
- 代码为 Apache-2.0；v1.5 / v2.0 权重采用 Nace.AI Open RAIL-M；DLM 权重为 CC BY-NC 4.0。商业使用前必须逐 checkpoint 检查许可证。

### 我怎么看

- Drex 把领域从“单纯监督微调”推进到“结果 reward + judge reward + stability”的 post-training，更接近 foundation decision model 的叙事。
- 对 SEA 最值得借的是 RLAF 的双 reward 设计，以及把一致性直接写进训练目标。
- 实验上建议先用 9B v1.5；35B v2.0 虽然每 token 只激活约 3B，但本地显存成本仍高。

### 2.6 RELOAD: Extending Reasoning in Typed Decision Models via Adaptive Looping

### 链接

- arXiv：https://arxiv.org/abs/2611.07736
- GitHub：**截至 2026-11-09 未找到可信的作者官方仓库。**
- 权重：**未确认论文中的六个训练 checkpoint 已公开。**

### 模型规模

论文覆盖六个模型：

- Von / ModernBERT-large：**395M**；
- Ettin：**400M**；
- Ettin：**1B**；
- Qwen3：**0.6B**；
- Qwen3：**1.7B**；
- Qwen3：**4B**。

### 方法

- 对模型做 2 epochs 全量 fine-tuning，数据是较宽的 typed-decision mixture。
- 选取中间 transformer block，重复执行 K 次，K 在 1–4 之间。
- 循环共享同一组参数，因此不会随循环次数增加模型参数量。
- 使用 damped residual update，避免反复迭代导致隐藏状态发散。
- 用 development set 拟合一个 controller，按样本难度选择循环次数；controller 不增加神经网络参数，可在 CPU 上运行。
- 论文报告 4 passes 的延迟低于 2×，且不增加权重显存；不过 activation、batching 和实现细节仍会影响实际吞吐。

### 结果

- 收益主要集中在长推理、干扰项多和结构复杂的任务。
- encoder 模型某些任务可提升到 **+23 points**；Qwen decoder 路线也有提升，但整体更小。
- distractor robustness 的提升也主要出现在 encoder。

### 我怎么看

- 这是这批工作里和当前 Kev/H20 最直接的方法增量：无需换成超大 backbone，就可以给 hard items 更多 latent compute。
- 它和现有 DecisionPivot / hard-v1 诊断天然匹配：可把 pair inconsistency、margin、entropy 或 controller score 作为加循环的触发信号。
- 最大问题是官方代码和 checkpoint 尚未确认公开，所以必须把复现实现与作者原实现区分开，并先做机制级复现。

## 3. 与 self-evolving / agent 决策特别相关的新工作

### 3.1 Jev-DLC：从 typed feedback 做 decision-level continual learning

### 链接

- arXiv：https://arxiv.org/abs/2610.31521
- 作者 GitHub：**论文和官方链接中未找到 Jev-DLC 方法仓库。**
- 第三方机制级复现（仅供参考，不是作者代码）：https://daiwk.github.io/auto-research/system-one/2610.31521-jev-dlc/

### 核心思想

- 用户接受或撤销一个 typed decision 后，不把全部历史重新塞回 context，也不在线微调大模型。
- 在冻结 scorer 上方维护两个有界状态通道：
  - conservative channel：积累重复 action identity 和长期偏好；
  - responsive channel：快速记录最近的 preferred-vs-rejected 方向。
- 用被选择/撤销的明确 action pair 做 passive-aggressive 更新。
- 不保存原始交互历史，不新增 scorer call，不在运行时做大模型 backward。

### 结果

- 新基准 TCPA-Bench 按时间顺序评估：一次 correction 只能通过影响未来 decision 获得信用，避免把当前标签泄漏给当前预测。
- TCPA-Repeat 总体 user-macro accuracy 为 **44.83%**，比 Recent-4 history replay 高 2.43 points。
- 至少有两次历史反馈后为 **56.07%**，比该深度最强比较高 7.54 points。

### 对 SEA 的意义

- 这是 10 月 20 日之后最直接命中“自我进化 agent”的工作。
- 它把 self-evolution 拆成“冻结能力模型 + 可审计的小状态更新”，比每轮 LoRA 更安全，也更容易回滚。
- 当前应优先复现 state transition 和 chronological evaluation contract，再决定是否接入 27B/9B scorer；不要把 CPU 状态机单测通过写成模型能力复现。

### 4.1 When Multiple Choices Are Correct

- 模型：Jev、Liquid d1、GPT-6 Luna Decisions。
- 现象：即使所有正确选项都排在 distractor 前面，仍有 28%–50% 的列表中至少一个正确项低于均匀概率 `1/n`。
- 把同一个正确选项复制五份后，不同副本的概率平均差距可达 17–79 percentage points。
- 最优 threshold 恢复完整正确集合的 exact-set accuracy 只有约 0.34–0.64。
- 结论：choice 概率适合做候选排序，**不能直接解释为每个候选独立为真的概率**。
- 对 SEA：多工具可同时适用时，不要在一次 softmax choice 上做固定阈值多选；应改成独立 `noul`、set-prediction head，或加入集合级训练目标。

### 4.2 RAG conflict typing

- 在 CONFLICTS 数据上比较 11 个 decision model。
- 10/11 达到或超过 Gemini 2.5 Flash，同时成本更低。
- 只把低置信度四分位样本升级给更强模型，8/11 的级联系统可追平 Gemini 3.8 Flash，成本约为其 25%–37%。
- 对 SEA：很适合做 evidence quality gate；重点不是单模型最高分，而是 **便宜 fast path + selective escalation**。

### 4.3 XDecideBench

- 9 个 suite、122 种语言、88,425 个文本、153,875 个 typed questions。
- 英语最优模型在约四分之一 suite-language cells 中显著输给其他模型。
- 在英语上调到 5% error 的置信阈值，迁移到德语和法语 XNLI 也会超标。
- 对 SEA：不能只测中文/英语平均准确率；confidence policy 必须按语言、任务和版本重新定标。

### 4.4 JevBreak

- 在 16 个任务、7 个模型、240 段文本上做定向 Slot Attack。
- 对“原本预测正确”的样本，攻击成功率约 32%–99%。
- 代表数字：Jev 1.14 为 31.6%，Jev 1.13 为 36.6%，Strands 2B 为 57.3%，Clef 为 69.1%，Decider 4B 为 78.9%，GPT-6 Luna Decisions 为 88.2%，GLiNER2.5 为 99.4%。
- 固定输出 schema 只限制“输出长什么样”，不限制“决定被谁控制”。confidence threshold 也不能稳定筛掉攻击。
- 对 SEA：Evidence / memory / tool description 都应视为潜在不可信输入；每个 model-task-version 要独立红队。

### 4.5 SLATE

- 合成约 1,000 个电商 API，任务由多层 procedure 构成，用 deterministic simulator 和最终任务状态自动评分。
- 评测 3B–12B 的六个开源 decision model 及其 backbone。
- 最好模型完整任务成功率只有 **5.0%**。
- 作者 GitHub 为 https://github.com/geshijoker/slate；截至 2026-11-09 仓库仍主要是项目页占位，论文所述完整 benchmark、simulator 和 evaluation harness 尚不能从该仓库稳定取得。
- 对 SEA：单步 tool routing accuracy 不能代表 agent 能力；错误会沿 8–16 步链条累积，必须测闭环 task completion。

### 4.6 Thinking Fast, Trading Late / OLIVIA

- 开源 fine-tuned 模型 Laya-Fin 约 **421M**，另测三个商业 decision model。
- 验证期 IC 为 0.055 / 0.065，但 2026 年盲测降至 0.020，t=1.7；没有预注册策略在交易成本后存活。
- OLIVIA 六项：point-in-time 输入、identity masking、validation-only selection、冻结计划 hash、一次性 unblinding、append-only audit trail。
- 商业模型仍能在 62%–74% 情况下识别被遮掉名称的公司，说明“去名字”不等于去记忆。
- 对 SEA：预测实验要冻结时间切分、输入可用时间和分析计划；否则很容易把回测选择偏差写成自我进化能力。

### 4.7 Structured Clinical Memory

- 30 个完全合成病例、120 个 typed questions。
- 原始 vignette 准确率 90.0%；加结构化 memory 后 93.3%，但 McNemar `p=0.219`，不能宣称显著准确率提升。
- log loss 从 0.258 降至 0.175；binary Brier 从 0.054 降至 0.022。
- 局限：合成样本、单作者标签、memory 是 oracle upper bound。
- 对 SEA：memory 可能先改善概率质量，再改善 top-1；实验应同时报告 accuracy、NLL/Brier 和 calibration。

### 4.8 Fast, Cheap, and Fair?

- 首个针对 Jev 招聘筛选的系统性 fairness audit。
- 同时改变显式 demographic attributes 和隐式姓名/表述线索，并用姓名替换、拼写变化构造 noise floor。
- 对 SEA：高风险 decision 不能只报整体 accuracy；至少要做 matched counterfactual、ranking shift、shortlist flip 和随机波动基线。

### 4.9 Jev with Foresight

- 把 Jev 与一个 language world model 组合：world model 对每个候选驾驶动作预测未来两秒车辆轨迹，再由代码转成碰撞和车道后果，最后由 Jev 选动作。
- 仿真并线碰撞率从 26.0% 降到 2.4%；NGSIM replay 从 48.2% 降到 2.8%；端到端每次决策约 0.25s。
- 结果仅来自仿真和 replay，没有实车测试。
- 对 SEA：这是很重要的架构模式——**decision model 不负责凭空想象后果，而是在显式候选后果上做选择**。它比单纯扩大 decision model 更接近可靠 agent。

### 4.10 Presentation Sensitivity

- 6 个数据集、9,000 个多标注样本、702,000 次 judgment。
- 干预位置、ID、作者身份、他人背书、问题 framing 和 rating rubric，但不改变被评文本。
- Jev 在摘要比较上的第二位置优势最高到 6.11 percentage points；反转 endorsement 会让 Perplexity 在 humor pair 上 40.40% 翻转；rejection framing 让 Clef 的摘要人类偏好一致率下降 23.36 points。
- 对 SEA：repeatability、presentation robustness、human alignment 是三个不同性质，不能拿“多跑几次稳定”代替“换表述仍正确”。

## 5. 对当前 H20 / SEA 实验的具体建议

结合仓库现有 Kev 4B / 9B / 27B、hard-v1 / devtools-v1 和 DecisionPivot 结果，建议把下一轮实验拆成四层。

### 5.1 模型层：补三个尺寸清晰的外部基线

1. **Jev-Style 2B v4.2**：低成本下界，验证方法在小模型上是否成立。
2. **IOTA Decide 4B**：和当前 4B 主线同尺寸的外部对照。
3. **Drex v1.5 9B**：和当前 9B 主线同尺寸的较强 post-trained 对照。

如果做多模态领域适配，再加 EO-Jev；Prism 105B 和 Drex v2.0 35B 只作为上界，不必放进每个 ablation。

### 5.2 方法层：优先做两个最小可证伪实验

#### A. Adaptive looping

- 在同一 checkpoint 上固定权重，只改变 loop policy。
- 比较 K=1、固定 K=2/4、entropy controller、pair-inconsistency controller。
- 分别报告 easy / hard / devtools、延迟、吞吐和每样本实际循环次数。
- 关键问题：收益是否只来自更多 FLOPs，还是 controller 真能把 compute 分配给困难样本。

#### B. Typed-feedback continual state

- 冻结 scorer，只实现 Jev-DLC 式两个状态通道。
- 严格 chronological：先 commit decision，再揭示 feedback；feedback 只能影响以后样本。
- 与 Recent-k history replay、user prior、no-adaptation 比较。
- 报告 user-macro、cold-start、两次以上反馈后的表现、状态大小、回滚和遗忘。

### 5.3 可靠性层：必须补的六组评测

1. **多正确选项**：exact-set、per-label AUROC、复制等价选项测试。
2. **option order**：全排列或 Latin square；报告 flip rate 和 probability variance。
3. **presentation**：ID、位置、肯定/否定 framing、rubric、署名和 endorsement。
4. **injection**：state、evidence、tool description、memory 分槽攻击。
5. **跨语言阈值**：至少中文/英文分开 calibration，不共享一个 automation threshold。
6. **闭环长链**：不只看单步准确率，报告最终任务完成率和错误传播位置。

### 5.4 证据层：避免把诊断集写成盲测

- hard-v1 / devtools-v1 如果用于 continuation targeting 或 prompt/threshold 调参，就只能叫 diagnostic/development set。
- 最终结论必须保留一次从未查看标签的新 blind set。
- 所有模型选择、阈值、温度、controller 和停止规则在盲测前冻结并 hash。
- 4B 之前改过 temperature 的结果，不应直接与未改温度的 calibration 数字横比。
- DecisionPivot 若没有可靠 overall accuracy gain，就把它定位为 failure-mode diagnostic，而不是主能力 benchmark。

## 9. 最简行动清单

如果只安排一周：

1. 下载 Jev-Style 2B v4.2、IOTA 4B、Drex v1.5 9B，统一转换为当前 eval schema。
2. 在现有 hard-v1 / devtools-v1 上只做诊断，不调最终 blind set。
3. 给 4B 加 K=1/2/4 固定循环 baseline，再加一个 entropy controller。
4. 加 option permutation、multi-correct copies、Slot Attack 三个小而强的鲁棒性集。
5. 冻结 temperature、阈值和 controller，生成一次全新 blind set。
6. 报告 accuracy 之外的 NLL/Brier/ECE、pair consistency、flip rate、automation coverage、latency 和 cost。

如果只选一个能形成论文新意的方向：

> **Adaptive latent compute + typed-feedback continual state + chronological blind evaluation**。

它把“当下更会判断”“遇到难题多算一点”“从后续纠错中持续适应”三个层次分开，最贴合 SEA / self-evolving agent 的研究主线，也能避开单纯堆更大 decision model 的同质化竞争。
